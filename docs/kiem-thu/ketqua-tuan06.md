## 4. DANH SÁCH 5 TEST CASE CHỜ CHỐT CONTRACT CONCURRENCY (REMAINING REVIEW REQUIRED)

Các test case xử lý xung đột dữ liệu đồng thời (Optimistic Concurrency) dưới đây đã được xác minh cơ chế stale write thực tế:
- **V1 hợp lệ (Base64 token)**: YES
- **A submit V1 thành công**: YES -> DB cập nhật dữ liệu và sinh **V2 != V1**
- **B submit original V1 (stale token)**: YES
- **Kết quả ghi đè**: **B KHÔNG overwrite A** (Dữ liệu của Session A được bảo toàn nguyên vẹn trong DB)
- **Runtime response**: Trả về **HTTP 302 RedirectToAction** + TempData Error notification thay vì **HTTP 409 Conflict** theo đặc tả ban đầu.

Lý do giữ trạng thái **Blocked**: **CONTRACT MISMATCH** (bất đồng bộ đặc tả HTTP status giữa 302 Redirect của MVC và 409 Conflict), hoàn toàn không phải do thiếu bằng chứng stale write.

2. **`TC-TRANSFER-005`**: Concurrency Shift Transfer Review -> Runtime trả `HTTP 302 Redirect` (`ShiftTransferService.ReviewAsync`).
3. **`TC-FORM-LEAVE-REVIEW-006`**: Concurrency Form Leave Review -> Runtime trả `HTTP 302 Redirect` (`LeaveRequestService.ReviewAsync`).
